# http-net v0.10.0 - Beta

**Date:** 2026-11-11
**Compare:** `v0.9.2...v0.10.0`

**The simplicity audit before 1.0.** The public API was checked once more
for one-line common uses with plain `?`, names a newcomer can read, and one
way to do each thing. Five places fell short. They are fixed here: four
signature changes, each a compile error at the line to change, and one
addition. No behaviour changes. `docs/MIGRATION.md` shows every change.

## What is http-net?

An HTTP/1.1 engine that does no I/O. Feed it the bytes a socket delivered;
it hands back requests or responses as borrowed views of those bytes,
decodes their bodies, and serializes what you send back. Parsing is strict:
a message two implementations could frame differently is refused with a
specific error, never repaired. Every buffer is bounded by configuration,
and each limit is checked before the bytes it governs are buffered.

## Changed

- **`parse_response_head` takes the request's `Method`.** The `Asked`
  struct is gone: pass `Method::Head`, `Method::Connect`, or the method
  the request had (`Asked::default()` becomes `Method::Get`).
- **`RequestHead::copy_into` returns `HeadFacts`.** It returned a
  `Result` that was never an error; drop the `?`.
- **`blocking::Connection::new(stream)`** takes only the socket. Set
  limits with the new `with_limits`, as on every other constructor.
- **The blocking time setters take a `Duration`** or `None`:
  `ServerConfig::with_read_timeout(Duration::from_secs(5))`, with no
  `Some`. `Some(..)` still compiles. The setters are no longer `const fn`.

## Added

- **`?` from `HttpError` into `std::io::Error`** (feature `std`), so a
  driver that returns `io::Result` needs no `map_err`. Running out of input
  is `UnexpectedEof`, a caller mistake is `InvalidInput`, anything the peer
  sent is `InvalidData`; the `HttpError` stays readable inside.

## Testing

All tests and doctests pass (`cargo test --all-features`), with new tests
for the `io::Error` mapping of every variant, `Connection::with_limits`,
and the setters taking a value, an `Option`, or `None`. The
`stateless_parse` fuzz target, which drives `parse_response_head` and
`copy_into`, ran 15 minutes on this code with no finding.

## Performance

No hot path changed. Interleaved against 0.9.2, nine rounds, no benchmark
moved past the 5% gate.

## Stability

The API stays the 1.0 candidate, now in this simpler form. 1.0.0 needs two
weeks with no API change, counted from this release, so it ships at the
earliest on 2026-11-25, on James's decision. The MSRV is Rust 1.85.

```toml
[dependencies]
http-net = "0.10"
```
